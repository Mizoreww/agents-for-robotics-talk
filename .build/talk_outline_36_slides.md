# 通用 Agent 如何获得可靠的机器人能力

## 叙事主线

**背景 → 问题 → 方法 → 实验与局限 → 总结。** 正文建议 60 分钟、36 页，讨论另计。文献与原帖范围仍截至 2026-09-10；本版重组叙事，不增加论文数量。

核心问题：**通用 Agent 怎样把理解、推理和编程能力，变成真实世界中可靠的行动，以及可以积累的机器人能力？**

先确立目标，再指出从现有能力到目标之间的三个缺口：

1. **行动缺口**：知道目标、生成合理计划，为什么仍不能稳定执行？
2. **世界缺口**：看到一次交互，为什么还不足以预测或测试新的行动？
3. **改进缺口**：获得一次失败反馈，为什么不等于下一次拥有更好的能力？

随后讲三条方法路线：**接入可执行接口，构建可试验的世界，运行可积累的改进过程**。每条路线均按“要解决的问题 → Big Picture → 关键机制 → 实验 → 局限”展开，而不是按论文发布时间展开。

三条路线可以组合，但不是所有系统必须依次经过的三个阶段。例如 ENPIRE 可以直接在真机上迭代，不必先通过 Real2Sim。

| 从具体失败推导核心研究问题 | 从执行、世界理解与持续改进三个缺口推导方法需求 |
| Filling the Interface Slot：给出方法之间的共同位置 | 将三类方法放回同一个机器人工作流，说明各自改的是哪一部分 |

复用的是论证结构，不沿用旧演示中对某一代 VLA 的概括性判断，也不假设分层能自动解决全部问题。

| 11 | 方法路线总览 | 1 | 三个问题分别对应 A 动作闭环、B 世界构建、C 自主改进；说明后文每个代表工作为何必须出现 |

## 三、方法 A：接入可执行的动作闭环（14 分钟）

**回答的问题**：如何让通用模型的推理结果变成可执行、可观测、可纠错的机器人行为？

**代表工作分工**：Code as Policies / VoxPoser 解释接口思路；CaP-X 拆开隐藏在接口中的能力；Claude 提供系统评测；Astra 提供最新真实案例。不是将它们硬凑成一种算法。

| 页 | 标题 | 分钟 | 讲解内容与主要画面 |
|---:|---|---:|---|
| 12 | Big Picture：Agent、执行工具与反馈 | 1.5 | 观测进入 Agent，输出程序/子任务/位姿，工具与控制器执行，结果返回 Agent；明确模型决策与底层控制的不同周期 |
| 13 | 关键机制：程序与几何接口 | 2 | Code as Policies 的控制流与函数组合；VoxPoser 的空间约束；用 CaP-X 高低层 API 展开图解释感知、坐标变换和规划隐藏在哪一层 [S03,S04,S16] |
| 14 | 实验一：Claude 的能力随接口变化 | 2.5 | 原报告按接口分组结果；直接操作完整成功率仅 0–5.5%；暂停仿真的 locomotion 不证明实时控制 [S09] |
| 15 | 实例机制：Astra 如何驱动真实机械臂 | 2 | Robocurve 的多路图像、本体状态、末端绝对位姿 move_to、IK、限速与调用预算；说明“直接控制”在此意味着什么 [S10] |
| 16 | 实验二：Astra 能完成哪些操作环节 | 2.5 | 放碗 19/20，对照 Fable 5.1 为 8/20；精细插入两者均 2/20。成功与失败配对，用任务阶段解释差异 [S10] |
| 17 | 实例扩展：绘画中的规划、反馈与校准 | 2 | SO-101 绘画：初始锚点、人类反馈、约一分钟动作规划、指令/校准更新；擦桌只补充行为种类 [S11,S23] |
| 18 | 路线 A 的边界：哪些部分仍交给专用系统 | 1.5 | VLA supervisor 不一定改善原策略；Gemini ER 2 / π0.7 提供推理与动作层协同的产业参照。结论落在 grounding、时间尺度与接口，而非“LLM 已取代 VLA” [S09,S19,S20] |

**回到问题一**：可执行接口与反馈让模型参与机器人行动，但精细接触、实时性、感知标定与低层控制并未因此自动解决。

**转场句**：“模型可以在当前环境里试着行动。但如果我们希望它理解动作后果，甚至先在虚拟环境里试验，就需要第二类能力：构建可试验的世界。”

## 三、方法 B：构建可试验的世界（10 分钟）

**回答的问题**：如何从有限真实观测，得到能运行、能比较、并逐步校正的仿真？这种仿真是否支持新的物理问题？

**代表工作分工**：Astra 原帖展示通用 Agent 跨工具调试的潜力；Agentic Real2Sim 提供流程与系统评测；SceneMosaic 补充最新的局部布局优化思路。

| 页 | 标题 | 分钟 | 讲解内容与主要画面 |
|---:|---|---:|---|
| 19 | Big Picture：真实观测到仿真反馈 | 1.5 | 图像/已知动作→几何与物理参数→可运行场景→重放比较→更新；分别标出相机、几何、动力学与动作参数，不把它们都称为“重建” |
| 20 | 实例：Astra 如何组织 Real2Sim | 2 | 多视角 RGB、动作、标定、资产、MuJoCo、Blender；配作者披露的 microphone 动力学失败。只将其作为能力演示，不当作基准验证 [S12] |
| 21 | 关键机制：Agent 与专用工具的分工 | 2 | Agentic Real2Sim 的视觉提取、物理先验、场景装配与 simulator-in-the-loop refinement；SAM3、SAM3D、FoundationStereo/Pose 和数值搜索的职责 [S13] |
| 22 | 实验：转换成功率究竟测量什么 | 2 | DROID-100 最佳后端 48 成功、8 部分、44 失败；解释最多 5 候选、3 judge 取最佳接受，不是多数投票，也不是物理参数准确率 [S13] |
| 23 | 方法扩展：SceneMosaic 的局部改进 | 1.5 | 图像初始化、物理布局稳定、局部 Critic–Actor 修复、组合多样性；24× 是特定场景生成基线对照，不是整个物理建模加速 [S14] |
| 24 | 路线 B 的边界：重放、预测与策略效用 | 1 | 分清外观像、已知动作重放、物理交互、未见动作预测与下游策略效用。说明现有证据在哪一层，缺哪些测试 [S12–S14] |

**回到问题二**：Agent 已能自动组织相当复杂的世界构建流程，但“能生成/重放”与“可预测、可训练”的距离还需要独立实验测量。

**转场句**：“有了执行接口，也有了可试验的环境，仍然不保证能力会自己提高。谁提出下一次修改、运行实验、判断改进，并把经验留下？这就是第三类方法。”

## 三、方法 C：组织可积累的能力改进（16 分钟）

**回答的问题**：如何把人类反复进行的调试、实验与学习，转成可运行、可信、能留下可复用产物的 Agent 工作流？

**代表工作分工**：Eureka / DrEureka 等说明已有自动化部件；ENPIRE 重点讲真机研发闭环；ASPIRE 讲技能积累；CaP-X 区分测试时改进与权重训练；RATs 补充任务到来前的探索。

| 页 | 标题 | 分钟 | 讲解内容与主要画面 |
|---:|---|---:|---|
| 25 | 已有自动化部件，还缺什么闭环 | 1.5 | Eureka / DrEureka 处理奖励、训练配方与迁移；RoboGen / AutoRT 处理场景与数据。把它们标在人工研发工作流的不同位置，不做四篇论文综述 [S05–S08] |
| 26 | Big Picture：ENPIRE 的真实实验循环 | 2 | EN / PI / R / E：环境、策略改进、rollout、结果反思。先展示完整系统，再讲 Agent 具体能修改哪些对象 [S15] |
| 27 | 关键机制：先让实验可复位、可验证 | 2 | 人类协助构建安全、reset 与验证，再固定环境 API 进入自主改进；可修改启发式程序、BC/RL 配方和策略。环境工程是方法组成，不是可省略的前提 [S15] |
| 28 | 实验一：ENPIRE 的高成功率与条件恢复 | 2 | 至多八次条件重试、部分任务从最难子阶段 reset；99% 不等于 one-shot precision 或独立 best-of-8。用该协议解释方法实际提高了什么 [S15] |
| 29 | 实验二：多机器人能否更快改进 | 1.5 | 1/4/8 机器人扩展；wall-clock、token 成本、MRU/MTU。说明更快得到结果与更高资源效率是两个问题 [S15] |
| 30 | 经验留在技能库：ASPIRE | 2 | 多模态轨迹→失败定位→程序修复→持久技能→演化探索；LIBERO-Pro Long 31% 对 4%，真实迁移只覆盖选定技能。区别外部记忆与模型权重学习 [S17] |
| 31 | 经验进入权重：CaP-X / CaP-RL | 2 | CaP-Agent0 的视觉反馈、技能合成与测试时推理；CaP-RL 用 GRPO 训练代码策略。真实 lift/stack 84%/76%，各 N=25；对比两种不同更新位置 [S16] |
| 32 | 任务到来前学习：RATs | 1.5 | 自主 play、技能获取、下游测试时冻结技能库；探索先于具体任务，且技能检索可能负迁移 [S18] |
| 33 | 路线 C 的边界：自动运行不等于持续进步 | 1.5 | 比较程序、技能库、世界参数和权重；回到独立验证、人工干预、复位成本、跨任务泛化与探索开销，避免把进程活动当作能力提升 |

**回到问题三**：已有方法能将部分调试与实验自动化，并留下策略或技能；跨环境可靠改进、验证可信度与成本控制仍未统一解决。

## 每条方法路线的统一讲法

1. **Problem**：先用一页/一句话说明上一部分留下的具体缺口。
2. **Big Picture**：先让听众知道输入、输出、Agent、工具和反馈的位置。
3. **Mechanism**：只展开最关键的两三个设计，明确哪些计算由 Agent 完成、哪些由专用模块完成。
4. **Evidence**：实验回答前面的问题；保留协议、分母、人工介入、重试、失败与成本。
5. **Limitations**：紧接实验说明未验证的部分，再回到总问题，为下一条路线铺路。

在方法开头重现同一幅总览时，仅作章节导航；不重复播放同一媒体或把相同证据图占用多页。

## 本版取舍

- **删除独立的“基石工作谱系”章节**：SayCan、Code as Policies、Eureka 等只在解释已有解法与缺口时出现。
- **删除独立的“大厂技术报告盘点”**：Gemini、π0.7 等作为动作接口的产业参照；GR00T N1 / MolmoAct2 的完整架构留附录。
- **不设“Astra 热点合集”章节**：操作、绘画、Real2Sim 分别进入对应问题；机械手 CAD 与擦桌保留为补充，不抢主线。
- **不把每篇论文讲成等长单元**：Claude 与 Astra 合起来回答行动问题；ENPIRE 是研发闭环主案例，ASPIRE / CaP-RL 解释两种积累机制。
- **证据类型不变**：论文实验、工业报告、独立评测与 X 演示仍明确区分；叙事更集中，不降低证据标准。

## 图片、视频与技术深度

- 正文计划 7 段不同短片，共约 3 分钟，包含在 60 分钟内；背景部分只用于提出机会，方法部分再解释机制与结果。
- 需要三幅同一套术语的总览：动作闭环、世界构建、能力改进。各图优先控制在五个主要模块内；复杂机制分步讲解，不交叉堆箭头。
- 讲机制时保留技术变量：坐标与动作时长、感知/控制频率、仿真参数、retry/reset 语义、更新对象与训练/推理预算。
- 原始结果图与失败案例保留；视频速度、等待删除、人类反馈和 kinematic replay 均注明。尚未完成所有短片的完整观看和剪辑。
- 附录容纳完整文献时间线、各方法协议、产业报告版本、更多 X 应用与实验细表。
- 视觉继续参考原 talk 的白底、青绿色、大图、留白；原模板及讲稿均不修改。
