# 机器人 Agent 的能力、接口与研究进展

## 综合判断

通用 Agent 在机器人领域的进展，正在同时发生在**任务执行**和**研发过程**两个层面。前者把语言、视觉与代码能力接入真实机器人，后者让 Agent 创建场景、调试仿真、设计奖励、运行训练和分析实验。两者容易在演示中被统称为“模型会做机器人”，但它们需要的接口和证明标准不同。

现有重点工作支持三个判断。第一，执行接口的设计是能力的一部分：同一模型通过子任务、程序、末端位姿或关节命令行动，会表现出不同上限。第二，反馈开始从一次截图扩展为多模态执行轨迹和可重复的真实实验。第三，改进的产物开始持久化为技能库、世界参数与策略，但这些产物并不等同于更新通用模型的权重。[S03–S06,S09,S13,S15–S18]

**尚不能从这些工作推出“通用模型已经取代机器人专用策略”。** 更符合证据的表述是：通用推理、专用视觉/几何工具、快速控制器、机器人基础模型和验证基础设施正在形成更灵活的组合。如何把这种组合变成跨环境、长期可靠且成本可控的系统，仍然是核心问题。

## 分类框架

这是一套用于比较的分析框架，不是某一论文提出的原始分类。

| 类别 | Agent 的输出 | 主要反馈 | 留下的产物 | 典型工作 |
|---|---|---|---|---|
| 在线规划与监督 | 子任务、技能选择、干预指令 | 当前观测、任务状态、失败信息 | 通常为任务内上下文 | SayCan、Inner Monologue、VLA supervision |
| 在线程序/几何控制 | 可执行代码、位姿、轨迹或空间约束 | 执行结果、视觉与本体状态 | 程序或当前上下文 | Code as Policies、VoxPoser、Astra 操作 |
| 世界与数据构建 | 场景、资产、物理参数、采集计划 | 渲染、仿真、几何/物理检查 | 世界模型、数据与场景 | RoboGen、AutoRT、Agentic Real2Sim、SceneMosaic |
| 自主策略研发 | 奖励、训练代码、策略、实验计划 | rollout、训练日志、独立验证 | 可执行策略、训练配方、权重 | Eureka、DrEureka、ENPIRE |
| 跨任务经验积累 | 技能摘要、程序、检索索引 | 失败轨迹、后续任务表现 | 外部技能库或更新后的模型 | CaP-X、ASPIRE、RATs |

最后一行是跨前几类的机制，不是互斥类别。同一个系统可以在任务执行时调用技能，在离线阶段更新技能，再通过训练把部分行为压入权重。

### 必须分开的三种“直接”

- **没有为当前任务训练专用策略**，不意味着没有使用预训练视觉模块、IK、轨迹生成与安全控制。
- **Agent 直接选择机器人动作参数**，不意味着逐伺服周期输出电机力矩。
- **Agent 能运行完整工作流**，不意味着初始搭建、复位、验证器和最终评测完全没有人类参与。

## 基石工作：保留机制，不堆时间线

| 工作 | 关键机制 | 今天仍然重要的原因 | 需要保留的限制 |
|---|---|---|---|
| [SayCan](https://say-can.github.io/)（2022） | 将语言相关性与技能可执行性结合 | 任务规划必须由机器人能力约束 | 可选择的技能和 affordance 模型预先存在 |
| [Inner Monologue](https://innermonologue.github.io/)（2022） | 将环境反馈重新输入规划 | 长程任务需要闭环，而不是一次生成计划 | 反馈形式与低层执行质量仍由系统提供 |
| [Code as Policies](https://code-as-policies.github.io/)（2022） | 用代码组合感知、几何与控制 API | 程序提供控制流、参数计算与复用能力 | 强 API 可能隐含大量机器人知识 |
| [VoxPoser](https://voxposer.github.io/)（2023） | 语言驱动 3D value maps，规划器执行 | 把语义目标转成空间可计算对象 | 依赖视觉 grounding、几何与规划器 |
| [Eureka](https://eureka-research.github.io/)（2023） | 奖励代码搜索、RL 与结果反思 | Agent 可以通过训练信号而非动作介入控制 | 策略性能包含大量下游 RL 计算贡献 |
| [DrEureka](https://eureka-research.github.io/dr-eureka/)（2024） | 将语言模型用于奖励和 domain randomization | 把研发自动化延伸到 sim-to-real | 不等于任何模拟器、任何任务都能自动迁移 |
| [RoboGen](https://robogen-ai.github.io/)（2023 / ICML 2024） | 自动生成任务、场景与技能学习过程 | 自动化对象扩展到训练环境本身 | 生成数量不等于有效难度、真实性与覆盖 |
| [AutoRT](https://auto-rt.github.io/)（2024） | 基础模型组织真实机器人任务与数据采集 | 真实数据生产也可以是 Agent 工作流 | 安全与人类参与是系统的一部分 |

这些工作在本次分享中作为机制来源。没有对它们重新进行逐项代码复现或跨论文性能排名。[S01–S08]

## 在线执行

### Claude Plays Robotics：能力评测必须控制接口

**重要性。** [2026-07-09 原报告](https://www.anthropic.com/research/claude-plays-robotics)将经典控制、运动与操作任务放在多种接口下考察。它不是单纯证明“Claude 能控制某台机器人”，而是直接暴露通用模型在具身问题上的接口依赖。

- **C09，主张**：较新模型在多个具身接口上进步，但控制和监督能力高度依赖具体设置。
- **E09，证据**：报告的操作部分显示直接控制的完整任务成功率约为 0–5.5%；VLA scaffold 明显改善性能。部分 VLA-familiar 任务上，加入 supervisor 仍低于 VLA 独立执行；在 VLA 本来不能完成的任务上则可能出现增益。来源：报告的 “Manipulation”、VLA supervision 相关图与 “Discussion”。
- **L09，边界**：部分直接 locomotion 实验在模型调用期间暂停仿真。报告讨论的约 83 Hz 控制需求与约 0.2–0.4 Hz 模型调用不在同一时间尺度，不能把暂停仿真的表现当作实时闭环表现。LIBERO-40 的 40 任务 × 5 seeds = 200 trials，与 Robocurve 的两项真机任务不是同一协议。

### Astra 真机评测：进步发生在哪个操作环节

**身份与来源。** [Robocurve 评测](https://openai.robocurve.org/gpt-6-astra/)发表于 2026-09-04，是独立机构的评测，域名并不是 OpenAI 官网。[OpenAI 模型文档](https://developers.openai.com/api/docs/models/gpt-6-astra)用于独立确认模型身份，不作为 Robocurve 机器人实验的背书。这里的 GPT-6 Astra 与 Google Project Astra 不是同一个对象。[S10]

- **C10，主张**：在作者设置的两项操作任务上，Astra 对粗放置任务有明显更高的观测完成率，但精细插入仍困难。
- **E10，证据**：YAM 双臂、三路图像与本体状态；模型调用 `move_to` 指定末端绝对位姿，IK 处理关节。20 次模型调用预算、medium reasoning、25% 速度上限和安全限制。放碗：19/20，对照 Fable 5.1 为 8/20、Fable 5 为 1/20。拼图插入：Astra 与 Fable 5.1 均为 2/20。来源：原页任务描述、Scoring、方法与逐 trial 表。
- **L10，边界**：样本小；放碗对照涉及不同 rig；试验没有交错执行；人工未盲评；人工 reset。成本为按标价估算，不能当作普遍部署成本。展示短片可能去掉模型等待，不能通过观看速度推断端到端延迟。

**解读。** 该结果足以提出“通用模型的视觉/空间推理可能改善低层技能之上的动作决策”这一重要研究方向，但不证明模型已解决接触、精度或通用机器人控制。阶段式失败信息比单个 95% 更适合深入技术分享。

### 产业路线参照

[Gemini Robotics ER 2 官方页面](https://deepmind.google/models/gemini-robotics/embodied-reasoning/)明确描述高层推理、任务进度判断、工具使用与向 VLA 交接运动执行；[Robotics 2 页面](https://deepmind.google/models/gemini-robotics/vla/)列出动作输出。它们适合支持“分层协同”的接口讨论。页面是截至 2026-09-10 的动态快照，不能把 2025 年首代 [Gemini Robotics 报告](https://arxiv.org/html/2503.20020)的实验数字直接移植到这些新版名称上。[S19]

## 世界构建与 Real2Sim

### 四个验证层次

外观像原场景、能重放原视频、符合当前动作下的物理交互、能预测新动作并帮助策略学习，是四个不同目标。越接近最后一个目标，越需要未见条件与干预实验；单段成功视频不能自动跨越这些层次。

以一个物体运动视频为例，错误的碰撞形状、摩擦或相机姿态有时可以互相补偿，使图像看起来接近。将动作速度或接触位置改变后，原来拟合良好的场景可能立即失败。因此，scene construction、system identification 和 downstream policy utility 必须分别报告。

### Astra Real2Sim：最值得讲的既是流程，也是失败披露

- **C12，主张**：原作者展示 Agent 组织多视角重建和仿真调试工作流，输入包含 RGB 与已知机器人动作。
- **E12，证据**：[原线程](https://x.com/Lingxiao234/status/2096992059731443923)描述相机标定、资产构建、物理参数迭代、MuJoCo 和 Blender；Agent 通过运行模拟、对比结果、修改参数闭环工作。
- **L12，边界**：[microphone 示例补充](https://x.com/Lingxiao234/status/2096992132527702382)明确说物理失败，展示的是 kinematic replay。作者指出刚体 proxy 无法表达所需的 snap-fit 柔顺接触。不能把整个线程的所有示例都标为“成功恢复动力学”。

这一案例的技术价值在于：Agent 能承担跨工具链的工程协调与反复调试；其上限仍受模拟器表达能力和观测可辨识性限制。后一句是从作者失败例得到的分析，不是对所有 Real2Sim 方法的否定。

### Agentic Real2Sim：流程自动化开始具备系统评测

**重要性。** [论文 v3](https://arxiv.org/html/2607.19190v3)（2026-07-24）把录制的交互 episode 作为转换单元，不只是生成静态物体。目标包括 actors、对象、相机、姿态、轨迹与接触关系的可运行组合。[S13]

- **C13，机制**：视觉提取、物理先验、场景准备与 simulator-in-the-loop refinement；Agent 使用 SAM3、SAM3D、FoundationStereo/Pose 等专用组件，配合确定性的优化/搜索。见论文 §3。
- **E13，结果**：DROID-100 保留全部 100 个输入 episode 作为分母。Gemma 4 31B 后端为 48 成功、8 部分、44 失败；其他后端成功数为 37–45。见 §4.1–4.3、Fig. 3。
- **E13b，接受协议**：先按 grasp、视频、运动统计过滤候选，最多取 5 个；3 个 VLM judge 分别评分，各自选择最佳候选，只要任一 judge 的最佳得分 ≥8/10，即记 replay success。不是三者多数同意，也不是均分通过。
- **L13，边界**：指标主要判断目标身份、最终位置、动作相似性与末端位置。它不是物理参数误差，也没有充分证明未见动作预测和下游策略泛化。柔性物体与人体示例主要是定性展示。$2.62/100 episodes 是某后端的模型调用费用，不含完整工具链、算力与人工成本。

![Agentic Real2Sim：DROID-100 replay 接受结果与模型调用费用](/home/limx/Desktop/agent_for_robotics/research/assets/agentic_replay_results.png)

图源：论文 Fig. 3。必须保留 failure 部分与右图的 logarithmic cost axis；不能只展示 48 或低价数字。

**解读。** 论文的重要进展是把工程流程标准化为可比较的 episode 转换；不同后端成功数较接近，提示工具链可能构成重要瓶颈。但要把这一提示确立为因果结论，还需要对视觉、几何、搜索与模型能力做配对消融。

### SceneMosaic：将昂贵的全局搜索分解为局部改进

[2026-09-04 预印本](https://arxiv.org/html/2609.05594v1)先建立场景与布局，再做局部 Critic–Actor 改进、物理布局稳定化和多样性组合。其关键思想是让 Agent 处理局部、可检查的问题，减少一遍遍重建整个场景的开销。[S14]

- **C14 / E14**：在 SceneEval-100 上，相对论文指定的 agentic baseline，作者报告约 24× 加速，并考察布局质量、物理违反和人类评价；参见主文方法与实验。
- **L14**：这些是场景/布局生成结果，不能外推为全套动态 digital twin 加速或机器人策略成功率。当前范围为房间级场景，不能自然延伸到整栋建筑和复杂接触动力学。

## 自主研发与经验积累

### ENPIRE：真正把真机实验纳入 Agent 改进环

按机器人自主研发这一语境，“EMPIRE”对应的重点工作应为 [ENPIRE](https://research.nvidia.com/labs/gear/enpire/)：**Agentic Robot Policy Self-Improvement in the Real World**，2026-06-18。另一篇同名 EMPIRE 检索结果讨论手部运动预测，与这里不是同一工作。

- **C15，机制**：EN 负责环境，包括硬安全约束、验证与自动 reset；PI 负责策略改进；R 运行真实 rollout；E 分析日志、研究改进方向并修改代码。支持启发式程序、BC、online/offline RL 与 VLA 混合。见 [论文 §2](https://arxiv.org/html/2606.19980v1#S2)。
- **E15，关键结果**：在真实操作任务上展示由实验反馈驱动的持续改进，并研究 1/4/8 台机器人的扩展。高成功率依赖论文 §3 定义的单条 rollout 内条件重试，至多八次重试；下一次尝试能够利用上一失败的信息。
- **L15a，成功率口径**：不能把 99% 写成 one-shot precision 或独立 best-of-8，也不能按独立伯努利公式反推单次成功率。报告的恢复能力是结果的一部分，不应被隐藏。
- **L15b，环境工程**：第一阶段有人类反馈，用于建立安全、复位与验证；进入自主改进后固定环境 API。部分 reset 把机器人直接放到最难子阶段的起点，而不是从任意整任务初始状态开始。见 §2.1 Automated reset、§3。
- **L15c，扩展成本**：更多机器人可缩短 wall-clock，但 token 成本上升，机器人利用率仍可能降低。MRU 与 MTU 提醒我们分别测物理资源与 Agent 推理资源。见 §3.3、§3.6、§4。

![ENPIRE 原始系统框架及实验改进示例](/home/limx/Desktop/agent_for_robotics/research/assets/enpire_framework.png)

图源：ENPIRE 论文。图中的环境构建、人类反馈、工具和实验循环都属于系统能力的来源，展示时不能裁成“Agent 直接自主获得 99%”。

**解读。** ENPIRE 的中心贡献是可重复真实实验的基础设施与工作流。相比只生成奖励或程序，它把真实 rollout 纳入迭代；但“实验可以自动运行”与“研究选择始终正确、可泛化且经济”仍是不同问题。

### CaP-X：把隐藏在 API 中的能力拆出来

[CaP-X v2](https://arxiv.org/html/2603.22435v2)（初版 2026-03，本次阅读版 2026-07-02）区分 CaP-Gym、CaP-Bench、CaP-Agent0 和 CaP-RL。其价值不只是又一个 code agent，而是对 **primitive abstraction、iteration、perceptual grounding** 做控制变量式分析。[S16]

- **C16 / E16**：主要受控分析覆盖 12 个模型与 7 个核心任务；CaP-Agent0 使用视觉差分、技能合成与并行推理等手段。CaP-RL 对 Qwen2.5-Coder-7B 用 GRPO 做 code-as-action post-training，论文 Table 4 报告真实 lift/stack 84%/76%，各 N=25。见 §3、§4、§5。
- **L16**：Zero-shot pass@1 是一条 trial 的口径，trial 内可有多个交互 turn，且不 reset。不能将 pass@1 误读为只调用一次模型。技能库在该实现中由已有成功 rollout 汇总合成，并不等于已经验证无限持续学习。CaP-Agent0 与 CaP-RL 必须作为两种不同的改进方式介绍。

### ASPIRE：经验沉淀为可检索的技能

[ASPIRE](https://arxiv.org/html/2607.00272v1)（2026-06-30）记录多模态执行轨迹，用于定位失败、修复代码、更新持久化技能，再通过演化探索扩展技能库。[S17]

- **C17 / E17**：论文 §2 给出执行引擎、技能积累和探索机制；LIBERO-Pro Long 的零样本迁移结果为 31%，对照 prior methods 约 4%，见 §3 与附录 C。真实双臂实验选取三个仿真技能作上下文指导；例如 can lift 从 13/20 到 19/20，同时减少调试 token，见 §3.6 Table 1。
- **L17**：保留技能并不意味着基座模型权重学习。未见任务的结果依赖特定 skill discovery 与测试划分。真机结果有价值，但只覆盖选定技能与实验设置；不可描述为在开放真实世界中已经闭合全部自主探索、复位与持续验证。

### RATs：将技能获取前移到自主探索阶段

[Playful Agentic Robot Learning](https://arxiv.org/html/2606.19419v1)（2026-06-17）让 RATs 在具体下游任务到来前提出探索任务、执行程序、验证与诊断，并将所得技能留作后续使用。[S18]

- **C18 / E18**：与完全任务驱动的修复相比，强调 play-time skill acquisition；测试时冻结技能库，区分探索产物与任务内搜索。
- **L18**：主要证据来自仿真；技能检索并非始终有益，错误或不适用的经验可能造成负迁移；VLM 验证器和探索开销也限制系统质量。

**横向结论。** ASPIRE/RATs 的外部经验库、CaP-RL 的权重更新、ENPIRE 的策略/训练代码改进是互补选项。未来更有价值的比较不是谁用了“self-improvement”这个名称，而是在相同总预算下，哪种产物能提升未见任务且减少下一次推理与试验成本。

## 值得继续追问的技术问题

以下为跨工作综合提出的研究问题，不是声称已经通过新颖性审查的论文选题。

### 1. 何时应该让 Agent 接管，何时应该交给策略

高层监督可能在陌生任务中有用，也可能破坏熟悉任务。应测量 Agent 介入的增量收益、原本成功任务的损害、反应延迟与接触风险，而不是只测组合后的平均成功率。可比较固定频率介入、事件触发介入和基于不确定性的交接；必须固定底层 VLA 与感知接口。[动机：S09,S10,S19]

### 2. 如何将高成本探索沉淀为低成本执行

外部技能、代码程序与权重更新分别承担不同形式的压缩。应同时报告探索/训练成本、测试时调用数、端到端延迟，以及技能检索是否造成负迁移。仅在测试时多试几次得到更高成功率，不等于获得了可重复调用的廉价能力。[动机：S16–S18]

### 3. 如何区分“重放拟合”与“世界模型正确”

应保留未见动作、速度、接触位置和初始状态，检查相机、几何、动力学各自误差，再测仿真能否改善策略选择、训练和真实迁移。对柔顺接触，还需要先确认模拟器的模型族能够表达目标现象；不应无限靠调参数补偿结构错误。[动机：S12–S14]

### 4. 谁来验证自主实验

用于搜索的奖励和最后报告结果的验证器应尽量独立。需记录自动复位失败、人工接管、误判成功和危险中止；保留完整失败分母。多机器人扩展还要测资源等待和物理串行环节，避免用总模型调用量替代有效实验进展。[动机：S13,S15]
